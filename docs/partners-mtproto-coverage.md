# Cobertura das APIs do Telegram no Infocard

## Decisão de objetivo

Aplicar Partners como método obrigatório de evolução. O resultado desejado é entregar, para a referência consultada, todos os campos e conteúdos de leitura que MTProto e Bot API realmente disponibilizam à sessão de bot, sem reduzir o escopo aos campos já exibidos pelo projeto. Código anterior é inventário, não padrão normativo.

A cobertura deve preservar objetos TL completos, respostas JSON Bot API, wrappers, campos escalares e aninhados, listas, metadados e conteúdo de mídia devolvido pelos métodos elegíveis. Coleções pagináveis devem ser lidas até o fim ou identificadas como parciais. A exportação estruturada preserva também valores vazios, zero e falso quando retornados. No modo completo, essa representação é apresentada em Rich Messages paginadas: cada linha mostra o caminho do campo e o valor, inclusive valores vazios, zero e falso; os anexos mantêm a representação detalhada. O sucesso da apresentação completa exige confirmação de todas as páginas ricas. Se apenas o fallback HTML for aceito, o conteúdo permanece entregue em formato alternativo e o resultado é marcado incompleto.

## Métodos atualmente tentados

| API | Métodos | Tipo de entidade | Uso na exportação completa |
|---|---|---|---|
| Bot API | `getChat` | Usuário, grupo, supergrupo ou canal | Preserva `ChatFullInfo` completo e tenta obter também chats pessoais, pais ou vinculados indicados na resposta. Para ID numérico que MTProto não resolve, tenta `getChat` e continua as leituras independentes por ID mesmo se esse método falhar. O tipo de peer derivado do ID direciona apenas chamadas compatíveis; para `PeerChannel`, não afirma canal ou supergrupo sem resposta API. Cada método mantém resultado ou erro separado; só payloads retornados contam como dados. |
| Bot API | `getUserProfilePhotos`, `getUserProfileAudios`, `getUserGifts` | Usuário | Pagina fotos, áudios e presentes recebidos/hosteados; tenta baixar os stickers dos presentes. |
| Bot API | `getUserPersonalChatMessages` | Usuário | Preserva até 20 mensagens do chat pessoal atualmente indicado no perfil e tenta baixar anexos compatíveis. |
| MTProto | `messages.getPersonalChannelHistory` | Usuário com canal pessoal associado | Pagina as mensagens do canal pessoal e preserva cada resposta `messages.Messages`; tenta baixar a mídia de cada mensagem. Esse método bot-only não concede histórico de conversas privadas nem de chats gerais. |
| Bot API + MTProto | `getAvailableGifts`, `payments.getStarGifts` | Catálogo global, sem vínculo com peer | Obtém os catálogos que a sessão pode consultar; as respostas completas e stickers acessíveis entram na exportação. O catálogo MTProto usa `hash=0` e não tem paginação. |
| Bot API | `getChatAdministrators`, `getChatMemberCount`, `getChatGifts` | Grupo, supergrupo ou canal | Preserva administradores, contagem e presentes pertencentes ao chat; pagina presentes e tenta baixar seus stickers. |
| Bot API | `getMe`, `getChatMember`, `getUserChatBoosts` | Estado do próprio bot e participantes de grupos básicos, supergrupos e canais | Registra a identidade do bot e tenta consultar seu status no chat. Usa participantes de `messages.getFullChat` em grupos básicos e páginas `channels.getParticipants`/administradores em canais; consulta `getUserChatBoosts` apenas para participantes de Channel e preserva índice entre peer e resposta. |
| MTProto | `channels.getParticipant` | Estado do próprio bot em canal/supergrupo | Faz uma consulta unitária usando `InputPeerSelf`; captura direitos e classe de participante quando acessível. Registra erro de acesso/não membro sem repetir para toda a lista. |
| Bot API | `getFile` | Mídia retornada por métodos acima | Percorre recursivamente respostas Bot API em busca de `file_id`, escolhendo a maior resolução em vetores de `PhotoSize`; baixa até o limite da Bot API e registra falhas/limites. |
| Bot API | `getStickerSet`, `getCustomEmojiStickers`, `getForumTopicIconStickers` | Conjuntos e emojis referenciados por chats, perfis e mensagens | Consulta conjuntos de stickers e emojis personalizados citados pelas respostas; em fóruns consulta também stickers permitidos para ícones de tópico e tenta baixar os arquivos acessíveis. |
| MTProto | `getFullUser`, `getFullChannel`, `getFullChat`, `getUserPhotos`, `getSavedMusic`, `getParticipants`, `getMessages`, `channels.getMessages`, `payments.getSavedStarGifts`, `premium.getUserBoosts` | Conforme tipo de peer | Preserva respostas disponíveis; usa `InputUser`/`InputChannel` com hash zero para os peers numéricos retornados pela Bot API; busca por ID as mensagens fixadas indicadas pelos objetos completos, pagina presentes Star para usuário, canal e grupo básico, e coleta boosts de usuários identificados como boosters. `getMessages`/`channels.getMessages` não enumeram IDs de mensagens. |

## Limites oficiais da sessão de bot

- As leituras Bot API incluem `getStickerSet` para nomes de conjuntos retornados por chats e `getCustomEmojiStickers` para IDs em campos/entidades, em lotes de até 200 conforme o limite oficial. Em chats de fórum, `getForumTopicIconStickers` também é consultado. `getUserGifts` e `getChatGifts` percorrem `next_offset` até o fim e preservam todas as respostas e presentes; a disponibilidade depende do que a API permite ao bot para aquele alvo. `getMe` fornece o ID da própria conta de bot para `getChatMember` consultar seu status no chat. Os estados de participantes vêm de `messages.getFullChat` em grupos básicos e de `channels.getParticipants`/administradores em canais e supergrupos. `getChatMember` e `getUserChatBoosts` são consultados por participante obtido quando aplicáveis; a documentação só garante informações de outros usuários para `getChatMember` quando o bot é administrador, e `getUserChatBoosts` também exige direitos de administrador. Cada resposta e falha é associada ao ID consultado. `getBusinessConnection`, `getBusinessAccountGifts` e `getBusinessAccountStarBalance` dependem de um `business_connection_id` de uma conexão empresarial ativa; presentes e saldo exigem ainda direitos específicos. Esse contexto não faz parte de uma consulta genérica por peer e não é presumido.
- As chamadas MTProto de leitura usadas incluem `users.getFullUser`, `channels.getFullChannel`, `messages.getFullChat`, `photos.getUserPhotos`, `users.getSavedMusic`, `channels.getParticipants` e `payments.getSavedStarGifts`. A chamada de presentes percorre o `next_offset`, registra respostas TL integrais e tenta baixar os documentos de cada presente retornado; também é tentada para grupos básicos com `InputPeerChat`, porque o schema oficial declara `peer:InputPeer`, e a resposta ou recusa específica do servidor fica registrada.
- `channels.getParticipants`, `photos.getUserPhotos` e `users.getSavedMusic` aceitam bots. O worker tenta no modo completo os filtros `recent`, `admins`, `bots`, `banned` (membros restritos) e `kicked` (membros banidos), cada um paginado e registrado separadamente. `channels.getParticipants` exige administração; o Telegram determina o que a sessão realmente pode ler. Filtros de contatos e menções dependem de contexto da conta/mensagem e não representam inventário geral do grupo.
- `messages.getHistory`, `messages.search`, `messages.getReplies`, `messages.getDiscussionMessage`, `messages.getMessagesViews`, `stories.getPeerStories`, `messages.getCommonChats`, `messages.getPeerSettings`, `messages.getChatInviteImporters`, `messages.getExportedChatInvites`, `channels.getAdminLog`, `channels.getForumTopics`, `messages.getForumTopics`, `channels.getForumTopicsByID`, `premium.getBoostsList`, `premium.getBoostsStatus`, `payments.getUniqueStarGift` e `payments.getUniqueStarGiftValueInfo` são exclusivos de sessões de usuário. Como a pessoa decidiu manter autenticação de bot, o Infocard não consulta histórico geral, buscas de mensagens (incluindo o filtro de todos os pins), threads, discussões, `stories.getPeerStories`, log administrativo ou lista completa de tópicos de fórum por esses métodos. O campo opcional `stories` retornado dentro de `users.getFullUser` é preservado quando o Telegram o inclui na resposta bot-callable. A exceção específica `messages.getPersonalChannelHistory` é bot-only: quando o usuário resolvido tem um canal pessoal associado, ela pode paginar as mensagens desse canal; não retorna o histórico geral de conversas. `messages.getMessages` e `channels.getMessages` aceitam bots, mas exigem IDs conhecidos; o worker usa o ID fixado mais recente retornado pelo perfil/chat. A Bot API `getChat` também devolve a mensagem fixada mais recente. Assim, os pins mais antigos e o histórico geral não são enumeráveis por esta sessão. `messages.getMessagesViews` altera o contador quando solicitado e, além de user-only, não é uma leitura sem efeito. `channels.getAdminLog` ainda requer administração do canal mesmo em uma sessão de usuário.
- `premium.getUserBoosts` é documentado para bots e consulta os boosts aplicados por um usuário específico; no modo completo, é tentado apenas para IDs cuja resposta `getUserChatBoosts` retornou ao menos um boost, evitando uma chamada MTProto duplicada para cada membro sem boost; falhas por ID ficam registradas. `stories.getBoostsStatus` e `stories.getBoostersList` não exibem o aviso oficial de que bots podem usar o método. A regra oficial da API MTProto diz que métodos chamáveis por bots exibem esse aviso; por isso esses dois métodos ficam fora do escopo de bot e não são chamados. Isso deixa o status agregado e a lista completa de boosters indisponíveis a esta sessão, mesmo que funcionem para usuários.
- Permissões, privacidade, FloodWait, ausência de dados e diferenças de layer podem limitar a resposta. Campo ausente não significa que o dado não exista.
- Escopo é leitura da entidade e das coleções que os métodos acima retornam. Nenhuma chamada de alteração é incluída.

## Auditoria de mensagens e pins — 2026-11-03

- As páginas oficiais marcam `messages.getMessages` e `channels.getMessages` como métodos que bots podem usar, mas ambos pedem IDs explícitos; não são APIs de listagem.
- `messages.getHistory`, `messages.search`, `messages.getReplies` e `messages.getDiscussionMessage` são exclusivos de usuários. A busca por pins utiliza `messages.search` com `inputMessagesFilterPinned`, então não expõe a lista completa de pins à sessão de bot.
- A Bot API `getChat` e `channels.getFullChannel`/métodos equivalentes expõem o ID da mensagem fixada mais recente. O código busca essa mensagem conhecida e serializa o resultado completo; não pode enumerar mensagens antigas sem uma API de histórico permitida para bots.
- `messages.getMessagesViews` é user-only e pode incrementar contadores de visualização; não entra no exportador de leitura.

## Métodos de leitura adicionais encontrados na auditoria — 2026-11-03

- `stats.getBroadcastRevenueStats` e `stats.getBroadcastRevenueTransactions` são marcados como compatíveis com bots nas páginas oficiais, mas declaram que não recebem parâmetros e não publicam tipo de retorno. O schema TL da camada 225 e o Telethon fixado não fornecem construtor executável para essas funções. Sem uma assinatura cruzada, a chamada permanece bloqueada; não concluir que os métodos não existem.
- `stats.getBroadcastRevenueWithdrawalUrl` também permite bots, mas inicia o fluxo de saque financeiro. É uma ação, não uma leitura, e fica fora do exportador somente de leitura.
- `payments.getStarsRevenueStats` e `payments.getStarsStatus` mostram métricas/balanço vinculados a peers, mas a documentação oficial diz “Only users can use this method”; ficam fora da sessão de bot.
- `payments.getStarGiftCollections` retorna coleções de presentes, mas a documentação oficial também o marca como exclusivo de usuários.
- `stats.getBroadcastStats`, `stats.getMegagroupStats` e `stats.getMessageStats` também são exclusivos de usuários. Logo os gráficos e métricas administrativas tradicionais não são obtidos por esta sessão.
- `channels.getParticipant` aceita bots e retorna um `ChannelParticipant` com usuários/chats relacionados. É consultado uma vez com `InputPeerSelf` para capturar a condição do próprio bot; não é repetido para toda a lista, pois a consulta unitária não acrescenta dados de perfil a usuários que `channels.getParticipants` já retornou.

Estas decisões restringem a cobertura ao que tem suporte explícito de bot, schema chamável disponível no SDK fixado, contexto/IDs já derivados da referência e finalidade somente de leitura. A matriz permanece parcial até cada família de métodos ter sido cruzada com o schema e a camada Telethon instalados.

## O que substitui

Antes desta evolução, o resolver mapeava uma seleção de campos, consultava no máximo uma foto e uma música, e não entregava uma exportação bruta completa. A implementação atual acrescenta preservação de respostas TL e Bot API, paginação de fotos, músicas, áudios e presentes via Bot API/MTProto, tentativas para campos de chat e mensagens pessoais, tentativa de listar participantes, exportação JSONL e pacotes de mídia. Isso amplia materialmente a cobertura, mas não conclui a meta de inventariar e chamar todos os métodos de leitura relevantes.

## Próximos passos necessários

1. Resolver a lacuna do grupo `stats.getBroadcastRevenue*`: confirmar uma assinatura de request/resposta em schema oficial vigente que também esteja presente no Telethon fixado. Até lá, não montar chamadas por suposição.
2. Comparar sistematicamente os demais métodos MTProto e Bot API relacionados a cada tipo de peer com os métodos disponíveis na layer Telethon instalada, registrando por método o aviso oficial de uso por bot, parâmetros/contexto necessário e dados retornados.
3. Implementar métodos elegíveis ainda ausentes quando acrescentarem dados ao objetivo; excluir e documentar os métodos que exigem sessão de usuário, contexto empresarial indisponível, identificadores externos não fornecidos ou direitos não presentes.
4. Confirmar no JSONL as respostas integrais, paginação e estado de cada chamada; verificar que mídias acessíveis foram empacotadas e que limites ou recusas aparecem como parciais.
5. Executar no Telegram com peer de teste e destino de entrega; inspecionar os JSONL e os pacotes recebidos. CI, sintaxe e aceitação de envio são verificações intermediárias.
6. Só declarar cobertura total dentro desse escopo após a matriz oficial e a execução real serem confirmadas.

## Critério de sucesso sustentado

Para cada execução completa, todas as respostas dos métodos de leitura inventariados e elegíveis foram serializadas sem perda, as coleções acessíveis foram paginadas até o fim, os anexos obrigatórios foram aceitos e inspecionados no Telegram, e cada campo ou coleção indisponível tem um estado e motivo explícitos. O sucesso continua limitado ao acesso realmente concedido pelo Telegram à sessão de bot.


## Referências oficiais consultadas

- [premium.getUserBoosts](https://core.telegram.org/method/premium.getUserBoosts): aceita sessões de bot e consulta os boosts aplicados por usuário. [stories.getBoostsStatus](https://core.telegram.org/method/stories.getBoostsStatus) e [stories.getBoostersList](https://core.telegram.org/method/stories.getBoostersList) não exibem o aviso de suporte a bots exigido pela orientação oficial [Working with bots](https://core.telegram.org/api/bots); esses métodos foram removidos do fluxo de bot.


- [getAvailableGifts](https://core.telegram.org/bots/api#getavailablegifts) e [payments.getStarGifts](https://core.telegram.org/method/payments.getStarGifts): consultam o catálogo global de presentes; a chamada MTProto aceita `hash` e pode devolver `payments.starGiftsNotModified`.


- [users.getFullUser](https://core.telegram.org/method/users.getFullUser) e [channels.getFullChannel](https://core.telegram.org/method/channels.getFullChannel): respostas completas e disponibilidade para bots.
- [messages.getFullChat](https://core.telegram.org/method/messages.getFullChat): grupos básicos.
- [photos.getUserPhotos](https://core.telegram.org/method/photos.getUserPhotos) e [users.getSavedMusic](https://core.telegram.org/method/users.getSavedMusic): fotos e músicas de perfil, com paginação e autorização de bot.
- [channels.getParticipants](https://core.telegram.org/method/channels.getParticipants) e [ChannelParticipantsFilter](https://core.telegram.org/type/ChannelParticipantsFilter): filtros e paginação; o método pode retornar CHAT_ADMIN_REQUIRED. A documentação [Telethon iter_participants](https://docs.telethon.dev/en/stable/modules/client.html) distingue membros restritos (`banned`) de banidos (`kicked`).
- [payments.getSavedStarGifts](https://core.telegram.org/method/payments.getSavedStarGifts): usuários e bots podem consultar presentes recebidos/guardados por um peer, com `next_offset` para paginação. [getUserGifts](https://core.telegram.org/bots/api#getusergifts) e [getChatGifts](https://core.telegram.org/bots/api#getchatgifts): listam presentes do usuário ou chat e paginam por `next_offset`; objetos `OwnedGift` incluem metadados e o objeto `Gift` com sticker. [getBusinessAccountGifts](https://core.telegram.org/bots/api#getbusinessaccountgifts) exige conexão e permissões de conta empresarial. [getChatMember](https://core.telegram.org/bots/api#getchatmember): retorna `ChatMember` e só garante o resultado para outros usuários quando o bot é administrador. [getUserChatBoosts](https://core.telegram.org/bots/api#getuserchatboosts): lista os boosts de um participante e exige que o bot seja administrador. [Bot API Message](https://core.telegram.org/bots/api#message), [PaidMedia](https://core.telegram.org/bots/api#paidmedia) e [getFile](https://core.telegram.org/bots/api#getfile): mensagens podem conter anexos em objetos aninhados; cada `file_id` acessível é elegível para download, sujeito ao limite oficial de arquivo. [getStickerSet](https://core.telegram.org/bots/api#getstickerset) retorna stickers do conjunto pelo nome; [getCustomEmojiStickers](https://core.telegram.org/bots/api#getcustomemojistickers) aceita até 200 IDs por chamada; [getForumTopicIconStickers](https://core.telegram.org/bots/api#getforumtopiciconstickers) lista stickers de emoji válidos para ícones de tópicos.
- [messages.getPersonalChannelHistory](https://core.telegram.org/method/messages.getPersonalChannelHistory): método **Only bots can use this method**, com parâmetros `user_id`, `limit`, `max_id`, `min_id` e `hash`; pagina mensagens do canal pessoal associado ao perfil do usuário. O método não substitui o histórico geral.
- [payments.getStarGiftCollections](https://core.telegram.org/method/payments.getStarGiftCollections): a página oficial marca este método como exclusivo de usuários.
- [payments.getUserStarGifts](https://core.telegram.org/method/payments.getUserStarGifts): a página oficial descreve presentes fixados no perfil de um usuário, mas declara que o método não recebe parâmetros e deixa o tipo de retorno vazio; a assinatura não aparece no schema TL da camada 225 nem no Telethon fixado. Não há como apontar a referência consultada por uma assinatura executável publicada. Os presentes do alvo são coletados por `payments.getSavedStarGifts` e Bot API; esse método legado permanece uma lacuna documental, sem chamada inventada.
- [messages.getHistory](https://core.telegram.org/method/messages.getHistory), [stories.getPeerStories](https://core.telegram.org/method/stories.getPeerStories), [messages.getCommonChats](https://core.telegram.org/method/messages.getCommonChats), [messages.getPeerSettings](https://core.telegram.org/method/messages.getPeerSettings), [channels.getAdminLog](https://core.telegram.org/method/channels.getAdminLog), [channels.getForumTopics](https://core.telegram.org/method/channels.getForumTopics), [messages.getForumTopics](https://core.telegram.org/method/messages.getForumTopics) e [channels.getForumTopicsByID](https://core.telegram.org/method/channels.getForumTopicsByID): limitações de autenticação de bot.
